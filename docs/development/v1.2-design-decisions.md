# v1.2 design decisions

## ADR V12-01: a bounded evidence pipeline before document breadth

Problem: owners have inventories but cannot safely turn arbitrary rows into
authoritative architecture declarations without explicit semantic review.

Decision: implement standard-library CSV/TSV first, immutable Pydantic records,
explicit mappings, content identities, hash-bound decisions, and native validation.
Use the existing bounded YAML event loader for profiles, drafts and decisions
(JSON is a YAML subset); reject aliases, tags, duplicates and excessive nesting.
Support UTF-8/BOM by default and explicitly selected CP1252 only. No encoding or
delimiter guessing, slugification, whitespace stripping or enum coercion.

Alternatives rejected: direct parser-to-YAML output loses trust boundaries;
automatic acceptance and inferred links invent declarations; a heavy document
framework adds unapproved dependencies before its value and safety are proven.

Dependency impact: none. Python 3.12/3.14 use `csv`, `hashlib`, `json`, `tempfile`
and existing PyYAML/Pydantic/Typer versions and licenses. No download is needed.
Optional workbook/document dependencies will require a separate decision covering
license, versions, offline installation, platform CI and hostile-container behavior.

Security: bound bytes before decoding, rows/columns/cells/field lengths before
building evidence, and diagnostics before returning a draft. Reject binary/control
text and malformed CSV. Formula-like cells remain inert text and receive warnings;
no spreadsheet output is produced. Treat source paths as local regular files,
reject symlinks/special files, never interpret cell contents as filenames or code.
All output is JSON/YAML with safe serialization; no source markup is rendered.

Compatibility: additive CLI group; analytical modules and native schemas unchanged.
An import can produce a valid inventory-only architecture. Valid does not mean
complete or deployed; completeness is explicitly asserted by the owner.

Acceptance: actual CSV and TSV inspect/map/review/emit workflows; unresolved rows
block emission; rejection/correction resolves duplicate identities; provenance is
accurate; deterministic equivalent inputs retain candidate IDs; emitted models
pass the original validator; adversarial and previous regression suites pass.
Local Windows checks do not imply hosted Ubuntu/macOS acceptance.

## ADR V12-02: explicit structured inventories and bounded OOXML

See [parser decision](v12-02-parser-decision.md). Standard-library restricted
OOXML is chosen because openpyxl/defusedxml are absent from both approved
verification environments. This is a finite inventory subset, not an unrestricted
Office parser. No new dependency, optional extra, download or cloud service is
needed; Python's PSF license applies. Broader workbook support requires another
parser and offline dependency decision.

Profile version 2 selects `json`, `xlsx` or `netbox-offline-v1`, then exact named
tables and declarative typed field mappings. Version-1 CSV/TSV controls remain
valid. Entity kinds stay asset/zone/interface/evidence-only connection.
Only typed asset-zone/interface-asset/interface-zone references are supported.
Unknown structures, ambiguous references and mapped formula values fail review
or require literal corrections; source reference identity is never silently
replaced following an owner rename. Cross-file reconciliation remains V12-04.

JSON uses strict UTF-8, finite numbers and duplicate-key rejection. JSON controls
use the same strict parser with the original control event/depth/byte ceilings;
YAML controls and native models keep their existing loader. This removes redundant
YAML scans of generated JSON without raising resource budgets. Typed numerical
evidence does not add floating-point values to native schema 1.

Privacy is format-specific: V12-01 retains unmapped CSV text; new adapters retain
only explicitly mapped allowed scalars, unknown-field counts and exclusion
diagnostics. Sensitive paths and authenticated URLs are forbidden. Formula text,
caches and external targets are excluded. A source digest still binds excluded
metadata. Candidate identity excludes irrelevant metadata, while the review hash
binds the exact source and retained evidence. Array positions remain relevant.

Development metadata becomes exactly `1.2.0.dev0`. Current identity tests assert
that literal version; historical 1.0.1/1.1.0 compatibility fixtures and the narrow
comparison allowlist retain their original exact expectations. CI artifact names,
console output, package metadata and installed verification agree. Historical tags,
release notes, assets and main are untouched.

## ADR V12-02R: exact numeric evidence and renewed structured review

Reproduction showed that binary float conversion rounded JSON and OOXML tokens
before evidence/review; JSON rounding and XLSX underflow could reach declarations.
Use a strict, frozen tagged numeric-token record instead of storing Decimal or
float in recursive evidence. Canonical integers remain exact integers; `-0`,
decimal scale and exponent spelling are retained. The 64-character budget remains;
exponents are limited to ±9999 and never expanded. Decimal is used transiently for
exact XLSX magnitude comparison, without context-sensitive arithmetic.

Structured draft/sidecar version becomes 3. All version-2 structured drafts fail
with `IMPORT_LEGACY_DRAFT`; regenerate from source and review again. Keeping a
rounded legacy number loadable would not make its evidence exact. Profile version
2, decisions version 1 and CSV/TSV version 1 remain supported. Hash binding is
unchanged. See [numeric policy](v12-02r-numeric-policy.md).

Normal decimal inputs remain useful. XLSX numeric styles, >15-digit precision
ambiguity, unsupported magnitude, formulas and merges still require literal
correction/rejection. The exact token is not proof of Excel's original input.
Importer YAML serialization quotes text, including exponent-shaped text that
PyYAML otherwise leaves plain; native scalar parsing and model identity stay intact.

Review ZIP creation uses a selected public-source allowlist, deterministic entries,
regular files, explicit bytecode/private-path rejection and a post-creation audit.
It does not recursively export a working directory or local acceptance evidence.
Actual wheel/sdist audits remain separate. The reported earlier manual ZIP was
not available locally; the approved earlier distributions passed their own audit.
