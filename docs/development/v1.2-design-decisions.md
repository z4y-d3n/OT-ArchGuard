# v1.2 design decisions

## ADR V12-01: a bounded evidence pipeline before document breadth

Problem: owners have inventories but cannot safely turn arbitrary rows into
authoritative architecture declarations without explicit semantic review.

Decision: implement standard-library CSV/TSV first, immutable Pydantic records,
explicit mappings, content identities, hash-bound decisions, and native validation.
Use the existing bounded YAML event loader for profiles, drafts and decisions
(JSON is a YAML subset); reject aliases, tags, duplicates and excessive nesting.
Support UTF-8/BOM by default and explicitly selected CP1252 only. No encoding or
delimiter guessing, slugification, whitespace stripping or enum coercion.

Alternatives rejected: direct parser-to-YAML output loses trust boundaries;
automatic acceptance and inferred links invent declarations; a heavy document
framework adds unapproved dependencies before its value and safety are proven.

Dependency impact: none. Python 3.12/3.14 use `csv`, `hashlib`, `json`, `tempfile`
and existing PyYAML/Pydantic/Typer versions and licenses. No download is needed.
Optional workbook/document dependencies will require a separate decision covering
license, versions, offline installation, platform CI and hostile-container behavior.

Security: bound bytes before decoding, rows/columns/cells/field lengths before
building evidence, and diagnostics before returning a draft. Reject binary/control
text and malformed CSV. Formula-like cells remain inert text and receive warnings;
no spreadsheet output is produced. Treat source paths as local regular files,
reject symlinks/special files, never interpret cell contents as filenames or code.
All output is JSON/YAML with safe serialization; no source markup is rendered.

Compatibility: additive CLI group; analytical modules and native schemas unchanged.
An import can produce a valid inventory-only architecture. Valid does not mean
complete or deployed; completeness is explicitly asserted by the owner.

Acceptance: actual CSV and TSV inspect/map/review/emit workflows; unresolved rows
block emission; rejection/correction resolves duplicate identities; provenance is
accurate; deterministic equivalent inputs retain candidate IDs; emitted models
pass the original validator; adversarial and previous regression suites pass.
Local Windows checks do not imply hosted Ubuntu/macOS acceptance.
