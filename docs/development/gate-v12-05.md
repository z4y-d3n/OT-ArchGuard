## B. Actual implementation

`otarchguard explore MODEL --output NEW_DIRECTORY` creates `index.html`, local
`assets.css`, `manifest.json`, paginated indexes and digest-named native/source/
candidate/group/decision/graph/analysis detail pages. Views cover zones, assets,
interfaces, every native declaration collection, selected documentary field values,
locations, transformations, contradictions and owner rationales. Native entities
link back to their origins. Graphical nodes connect to source-qualified candidates
and documentary edges. There is no JavaScript, server or external service.

`--provenance SIDECAR` supports saved project-provenance version 1 with exact model
binding and retained-review reproduction. Other sidecar versions are explicitly
incompatible; omitting the option produces a useful model-only Explorer without
invented provenance. Neither visualization mode requires original source files.
The [complete installed tutorial](../../examples/explorer/README.md) uses the existing
six-device fictional mixed XLSX/JSON/CSV/draw.io project and a separate native
transport/forwarding/policy example. See the [six ADRs](v12-05-architecture-explorer.md).

## C. Trust and analytical correctness

Dashed documentary connectors and graphical direction remain evidence only.
Owner-confirmed native declarations retain exact fields and independent solid-line
direction. Explicit `--trace SOURCE:SERVICE`, `--check` and `--scenario ID` options
regenerate analytical results through the existing engines on the same validated
snapshot. Analytical pages retain exact endpoint binding, direction, transport,
inclusive ports, model identity, witness/frontier explanations and qualifications.
Old HTML is not an input. No query is invented or evaluated by default. Negative
evaluated intervals differ from `Not evaluated`, unsupported input and unmodeled
paths. Empty checks establish no global security conclusion. Existing engine and
standalone report bytes are independently regression tested and remain unchanged.

## D. Security and privacy

One reviewed HTML/SVG escaping boundary, renderer-only filenames/links/classes and
an actual-output parser prohibit active source markup and remote references.
Strict CSP provides defense in depth, independent of escaping. Hostile native and
documentary labels/rationales remain inert or fail controlled validation. Bidi
formatting controls are visible markers. Source URLs remain text. Original files,
source paths, unmapped metadata, style/geometry payloads and private development
receipts are excluded. Common absolute host-path spellings are withheld. Default
output remains sensitive full-detail documentation; no public-safe mode or universal
secret detection is claimed.

Bounded regular-file reads reject special files and ancestor links/junctions.
Strict sidecar schemas, exact versions, source/draft/manifest/model digests,
recomputed reconciliation, review decisions and identity/declaration indexes fail
closed. The retained-review helper is shared with emission, whose original source
reproduction remains mandatory. Hashes do not authenticate authorship. Sites stage,
audit and publish as a complete fresh directory; failures leave no partial output.
Single-writer and crash-durability limits are explicit.

## E. Accessibility and browser limits

Pages have semantic headings, main/navigation landmarks, skip links, visible focus,
captioned tables with column headers, focusable overflow regions and SVG titles/
descriptions with complete linked text alternatives. System typography, wrapping
IDs and responsive cards support ordinary reading. Default text/link/background
contrast is mathematically tested; color alone conveys no trust state. All core
information and links work structurally without JavaScript because none is emitted.

The available browser tool rejected `file://` navigation by protocol policy. No
workaround, local server, alternate browser surface or dependency download was
used. Actual file-origin CSS/CSP, keyboard focus, 200% zoom, small-viewport rendering,
console/network behavior and assistive-technology review are **NOT VERIFIED**.
Parsed markup and Python network-denial probes do not establish those behaviors or
WCAG certification. This limitation is distinct from the executed structural tests.

## F. Performance and ceilings

`benchmarks.explorer` regenerates small (20 assets/30 interfaces/40 connectors),
medium (150/200/250), larger (500/600/750) and adversarial repeated-label/long-rationale
projects. Final `performance.json` records actual input/index/render times, file
count, total bytes, largest HTML/SVG, internal-link count, repeated bytes and
separate Python allocation peaks for each size. No performance numbers in this
public dossier substitute for the final installed-source measurements.

Indexes and paginated reverse links avoid repeated all-evidence rendering.
The inherited overview has explicit summary thresholds. Zone cards show at most
20 assets; relationship views show at most 20 endpoints and 32 rows, reporting
omissions while retaining complete linked text. Site rejection ceilings are
24,000 files, 1 MiB per HTML/CSS, 4 MiB manifest and 256 MiB total. There are at most
16 explicit requested analytical operations. Sidecars retain 40 MiB/depth-40 limits.
Ceilings are independent bounded rejection limits, not universal capacity promises.
