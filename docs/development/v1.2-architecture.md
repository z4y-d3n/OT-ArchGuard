`records.py` retains version-1 profiles and adds version-2 structured profiles,

`tabular.py` preserves CSV/TSV parsing and identities. `json_inventory.py` parses

One profile selects up to sixteen collections/sheets in one source. Only asset,
zone and interface candidates can become declarations. Connection candidates must
be rejected before other declarations emit. Sites, VLANs, roles and cables never
produce security zones, forwarding, transport, listeners or rules. The owner
supplies all remaining model context and confirms every declaration.

Structured candidate identity binds mapped typed values, transforms, table/profile
semantics and duplicate occurrence. JSON array positions remain relevant; object
property order and excluded metadata do not affect these IDs. XLSX sheet order
and cell coordinates do not affect candidate IDs when names and mapped content
are unchanged. Duplicate entities are never merged. Source bytes, retained
locations, counts and diagnostics bind the draft hash: excluded metadata changes
still require fresh review. Locations use basenames, pointers, sheet names/IDs and
A1 coordinates, without timestamps or absolute local paths.

References resolve only through a selected table and its unique proposed ID.
Asset zone references target zones; interface ownership/placement references
target assets/zones. Other combinations, including cycles, are rejected. Evidence
keeps raw source identity separately from proposed values, target candidate ID,
owner correction and emitted model ID. Rejected/renamed targets require explicit
dependent corrections; native validation checks the result. Cross-file matching,
name/IP matching and automatic merging are outside this gate.

Mapped formulas, missing/wrong types, styled numeric ambiguity and unresolved
references require literal correction or rejection. Cached values never waive
review. Every candidate requires a reasoned decision; templates never confirm.
New-format unknown values are excluded; sensitive field paths are forbidden.
External targets/formula text/caches are excluded. CSV/TSV retains its original
unmapped text contract; owners must review that older evidence before sharing.

Drafts retain the 5 MiB/depth-32/200,000-event control ceilings. JSON controls use
a strict JSON parser with equivalent structural event accounting, avoiding repeated
YAML scanning and permitting typed numeric evidence. YAML controls retain the
original loader. Native YAML scalar semantics and decision model types are unchanged.
Sidecars have a 5 MiB emission ceiling. Resource rejection precedes publication.

Emission reopens the original regular file, reproduces the draft, verifies decisions
and corrections, validates the combined model using the unchanged schema-1
validator, and verifies normalized bytes. Model and sidecar publish together by
no-overwrite rename. File publication uses Windows rename/POSIX hard links.
V12-01 local single-writer and crash-durability limits remain. Digests are change
detection, not signatures. Analytical modules, model hashes, native resource limits,
schema 1 and trace/report version 1 remain unchanged.

V12-02R introduces `numbers.py`: canonical integers remain exact integers;
negative zero and decimal/exponent tokens retain their lexeme and numeric category

drafts/sidecars now use version 3; profiles remain version 2, decisions version 1,

unchanged native YAML loader. Native integer/boolean values keep their types.

## Graphical evidence (V12-03)

`xml_safe.py` reuses the XLSX callback-budget implementation; XLSX keeps its
existing limits/codes. `graphml.py` and `drawio.py` produce shared `GraphDocument`
evidence through `graphical.py`, then project explicitly selected values into
`map_extracted`. No second review/emission pipeline exists. Profile version 3
and draft/sidecar version 4 add scoped graph records; existing profiles/drafts
serialize as before. Decisions remain version 1.

All selected nodes, groups, layers and connectors remain in the graph sidecar.
A profile may omit an `edges` table: `connections: evidence_only` explicitly
requests retention without native candidates, and complete model/asset review is
still required. Selecting an edges table adds connection candidates, each of which
must be rejected with a rationale. Neither choice creates transport or forwarding.
Group-to-zone proposals require an explicit `groups` table and owner confirmation.
GraphML keys use explicit IDs, typed defaults and exact numeric evidence.
The graph profile's scopes, source hash, fields and relationships bind review.
See [graphical ADRs and boundaries](v12-03-graphical-formats.md).

## V12-04 project orchestration

The development pipeline now accepts a version-1 Import Project manifest,
retains each accepted adapter draft once in a source-qualified catalog, builds
bounded exact match/conflict groups and applies explicit owner partitions.
Project draft/decision versions are distinct from all single-source versions.
Field conflicts, reference corrections, final identity and native context remain
reviewed separately. Emission reproduces every source and validates schema 1
before publishing the complete deterministic bundle. See the
[project architecture and six ADRs](v12-04-projects-and-reconciliation.md).
V12-04 itself introduces no analytical-engine semantics or visual Explorer.

## Architecture Explorer (V12-05)

`explorer_data.py`, `explorer_html.py` and `explorer.py` provide bounded input
verification, one HTML/SVG safety boundary, indexed projections and staged static
publication. The retained project review helper validates catalog/decisions without
original files; emission still reproduces sources first. Hash-named detail pages,
paginated indexes, local CSS and exact query regeneration preserve three trust
layers without changing native schema, hashes or the analytical engine. See the
[six Explorer ADRs](v12-05-architecture-explorer.md) and
[installed walkthrough](../../examples/explorer/README.md).

## Documentary evidence and compact presentation (V12-06)

Version-4 document profiles and version-5 source drafts add located observations
without a second native model. Existing project controls, explicit partitions,
source hashing, acknowledgment and stale-source reproduction remain authoritative.
The shared OOXML archive boundary serves XLSX/DOCX/PPTX; format-specific structural
readers retain their own policies. Explorer contract 2 groups low-value detail
records through a deterministic location index and preserves native/analysis views.
Read the [V12-06 ADRs](v12-06-document-evidence-and-explorer.md).
