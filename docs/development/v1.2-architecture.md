# v1.2 architecture — Gate V12-01

Status: development on `codex/v12-ingestion-foundation`, based on immutable
v1.1.0 commit `0ffc7c6ce9a1963b3018c695a6c5748f25a7307e`, tree
`18c17133fe03a3b55c57978b454b85fd2d18fcfc`.

The import subsystem is an independent evidence boundary. Its pipeline is:
detect → bounded parse → explicit mapping → candidates/conflicts → owner review
→ confirmed declarations → existing `api.validate_bytes` → local artifact bundle.

`ingestion/records.py` defines immutable versioned source, location, field,
candidate, conflict, diagnostic, profile, draft and owner-decision records.
`ingestion/tabular.py` supplies the first adapter and its capability contract.
`ingestion/workflow.py` performs mapping, review, validation and publication.
`ingestion/cli.py` adds the `import` command group to the existing Typer app.
Later adapters produce the same evidence records; they do not write model YAML.

The first gate maps exactly one table to assets, zones, interfaces, or evidence-only
connections. A connection candidate cannot be emitted. The owner must reject it
or wait for a separately designed relationship review workflow. Other collections,
SUC metadata and any policy are explicit owner declarations in the decision file.
No default zone, scope, kind, classification, address, policy or direction is guessed.
No imported object reaches the engine before owner confirmation and validation.

Candidate IDs depend on exact row content, duplicate occurrence, mapping and kind,
not physical row order or local path. Duplicate identities remain conflicts, even
for identical rows. Owner corrections or rejection must resolve them. Draft hashes
bind all source bytes, locations, profile and diagnostics: reordered source rows
retain candidate IDs but require fresh review. Provenance includes raw and normalized
bounded fields, transformations, unmapped values, decisions and final model IDs.
It uses source basenames and SHA-256, without absolute local paths or timestamps.

The emitter rereads the original source and reproduces the draft before accepting
hash-bound decisions. These digests detect accidental change; they are not digital
signatures or proof of the reviewer's identity. Decision files are trusted owner
inputs and require an explicit reviewer, rationale and model confirmation.

Schema 1, model hashing, graph, policy, trace/report version 1 and all analytical
modules retain their contracts. Import metadata lives in a sidecar. Output is a
new directory containing `architecture.yaml` and `architecture.provenance.json`,
staged together and published by a same-filesystem directory rename. Existing
destinations are refused. Drafts and templates use atomic no-clobber file writes.
There is no force-overwrite mode. Runtime requires no network or new dependencies.

Version metadata remains 1.1.0 during this foundation gate to avoid a premature
release identity change and preserve the existing exact-version tests. This branch
is unreleased development, not the published v1.1.0 distribution. A future gate
must explicitly coordinate development-version metadata and its identity tests
before distributing a v1.2 candidate. Never publish builds from this gate as 1.1.0.
