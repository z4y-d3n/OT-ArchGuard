## XLSX

Select exact sheet names once each, with stable `sheetId` and A1 provenance.
Headers must be nonempty literal strings without equivalent/duplicate names.
Missing cells differ from explicit empty strings. Displayed formats are not values.
Text identifiers retain leading zeros; numeric IDs require explicit typing/prefix
or correction. Styled numbers, dates/errors, precision-sensitive numbers and
formulas require literal correction/rejection. Formula caches/text are excluded;
cache presence is diagnosed. Merged mapped cells require correction. Hidden sheets
are diagnosed and still need explicit selection. Shared/inline rich text is bounded.

Only UTF-8 transitional OOXML with worksheet parts `xl/worksheets/sheetN.xml` is
supported. Reject macros, embeddings, drawings, comments, charts, pivot tables,
defined names, orphan sheets, unsupported package parts/worksheet constructs and
strict OOXML namespaces. No `.xls`, `.xlsm`, encryption, date conversion, rendering,
formula evaluation or refresh. External targets are excluded and never fetched;
external workbook parts fail. Archives are never extracted. Traversal,
duplicate/case-conflicting names, special/encrypted members, unsupported compression,
corrupt XML/ZIP, DTDs, entities and processing instructions fail closed. XML budgets
also cover unselected/unused parts. This is not universal Excel compatibility.

## JSON

Strict UTF-8 without BOM: no duplicates, comments, NaN/Infinity, unbounded exponents,
surrogates or control text. Each selected collection is an array of objects.
RFC 6901 pointers use `~0` for `~`, `~1` for `/`, empty root and canonical array
indexes. No wildcards, JSONPath, includes or executable expressions.
Missing/null/empty strings/booleans/numbers and empty containers remain distinguishable.
Mapped nonempty containers are unsupported and their values are excluded.

Fields declare string/integer/number/boolean types; bool never satisfies integer.
Transforms: exact, trim, lower, upper, IPv4 host/prefix canonicalization and explicit
string prefix. Every transform is recorded. No implicit prefix is supplied.
`missing: error` rejects absent values; default `review` requires correction.
Object property order is irrelevant; array position is relevant.

Integer tokens remain exact integers except `-0`, which needs its lexeme.
Decimal/exponent numbers use a tagged raw value with `numeric_token` and
`numeric_category`; e.g. `1.00` stays a number with normalized text `1.00`.
Neither rounding nor exponent expansion occurs. `1e-400` and `1e309` are bounded
finite JSON evidence, independent of binary64 range. A string that looks numeric
remains a string; a source object resembling the tag remains an unsupported object.
XLSX preserves these tokens but requires correction for unsupported Excel magnitude,
styles and precision ambiguity. No recovery of pre-OOXML precision is claimed.

New structured drafts/sidecars use version 3. Version-2 profiles remain valid;
version-2 drafts are rejected and must be regenerated/reviewed from source.
CSV/TSV draft version 1 and owner decisions version 1 remain unchanged. See
[numeric policy and migration](v12-02r-numeric-policy.md).

## Offline NetBox contract

A deliberately combined offline envelope, not arbitrary NetBox API/version
compatibility. Root keys: `export_format: otarchguard-netbox-offline`,
`export_version: 1`, and optional `devices`, `interfaces`, `ip_addresses`, `vlans`,
`prefixes`, `cables` arrays. Unknown root collections/versions fail. Stable IDs are
strings/integers. Duplicate IDs, missing references, non-interface assignments,
reused IPs/multiple addresses per interface, malformed canonical IPv4 prefixes,
IPv6 and conflicting/unresolved VLAN references fail deterministically.

Devices have `id`, `name`, optional role/site/location scalar or `{id,name}` labels.
Interfaces have `id`, `name`, `device: {id}`, optional VLAN references.
IP records have `id`, `address` (IPv4/prefix), `assigned_object_type: dcim.interface`,
`assigned_object_id`. Explicit `/@assigned_ipv4` maps only interface `ipv4` by a
unique assignment, retaining the real IP pointer and projection rule. Missing
addresses require correction/rejection. Prefix/VLAN objects remain checked
metadata; they never generate zones/policy. Cable terminations are unsupported,
excluded and diagnosed; mapped cable candidates can only be rejected.

Only mapped allowed scalar metadata is retained. Unknown record fields are
counted/diagnosed without values. Sensitive field paths (passwords, tokens,
credentials, API/private keys, notes/comments, URLs) and mapped authenticated URLs fail.
Unknown values never enter new-format reports. Credentials are never used.
See [Import Studio](../import-studio.md) and the
[parser decision](v12-02-parser-decision.md).

## Graphical formats (V12-03)

See the [exact supported subset, profiles and resource budgets](v12-03-graphical-formats.md).
Only `.drawio`, `.graphml` and explicitly adapter-selected `.xml` are accepted.
Extension alone does not establish compatibility: the root/namespace is verified.
Compressed draw.io uses canonical Base64, bounded raw-DEFLATE, strict percent
escapes and UTF-8, then the same XML checks. Input/expansion limits are cumulative
across selected and unselected pages. Namespaces consume XML budgets.

Profile version 3 selects exact scope IDs and at most one `nodes`, `groups`,
`edges` table. The existing field types/transforms/constants/references apply.
`nodes` proposes assets; `groups` proposes zones; `edges` is evidence only.
`/scoped_id` supplies a deterministic 64-character proposed native ID based on
scope and source ID; `/id` preserves the original ID and may require correction.
Reused IDs across pages do not merge candidates. Duplicate IDs within a scope fail.
Text shapes/layers remain evidence without asset proposals. GraphML attributes
are selected by `/attributes/KEY`, using key IDs, not inferred attribute names.
Unsupported values are excluded. Core labels are retained as inert bounded text.
No label/style/group/arrow/attribute is an authoritative security declaration.
Visually connected assets are not automatically reachable.

Errors: `IMPORT_GRAPH_ROOT`, `IMPORT_GRAPH_STRUCTURE`, `IMPORT_GRAPH_UNSUPPORTED`,
`IMPORT_GRAPH_ID`, `IMPORT_GRAPH_DUPLICATE`, `IMPORT_GRAPH_PARENT`,
`IMPORT_GRAPH_DIRECTION`, `IMPORT_GRAPH_ATTRIBUTE`, `IMPORT_GRAPH_SCOPE`,
`IMPORT_GRAPH_XML`, `IMPORT_DRAWIO_BASE64`, `IMPORT_DRAWIO_DEFLATE`,
`IMPORT_DRAWIO_PERCENT`, `IMPORT_DRAWIO_STYLE`, plus existing mapping/review/output
errors and `LIMIT_EXCEEDED`. `GRAPH_DANGLING`, `GRAPH_EXTERNAL`, `GRAPH_MARKUP`,
`GRAPH_STYLE`, `GRAPH_LAYER`, `GRAPH_VISIBILITY`, `GRAPH_METADATA` are bounded
review diagnostics. External targets are omitted and never followed. No general
secret detection is claimed; review labels and mapped values before sharing.

## V12-04 multi-source project controls

Project manifests reference existing CSV/TSV, XLSX, JSON, offline NetBox, draw.io
and GraphML adapters and explicit existing profiles. No new source adapter is
added. Strict project manifest, draft and decisions each begin at version 1;
project controls never reinterpret single-source draft versions. Read the
[project reference](v12-04-projects-and-reconciliation.md) for exact fields,
paths, resource ceilings, identity proposals, conflict review and native emission.
The [synthetic walkthrough](../../examples/import-studio/projects/README.md)
combines four heterogeneous sources into one owner-reviewed schema-1 model.
