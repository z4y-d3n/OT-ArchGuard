### PCAP Evidence Studio source

The image is the complete diagram from a real `capture compare` report, using
`examples/capture-studio/architecture.yaml` and the first three frames emitted by
the existing `tools.capture_workloads.write_pcap(..., count=3)` fictional writer.
Those frames are the engineering SYN, its reverse SYN/ACK and the HMI SYN.
The resulting three findings are model-compatible, direction-uncertain and
model-discrepant, respectively. They are evaluator results, not added annotations.

The compact preview is distinct from the packaged ten-record and extended
twelve-record [capture walkthrough](../../examples/capture-studio/README.md).
Only RFC 5737 documentation addresses and locally administered fictional MACs
are used; there is no industrial-plant capture, customer network or private data.
The owner associations are explicitly authored fixture decisions, not a real
owner review or cryptographically authenticated identity.

From a checkout or extracted source distribution, with the released CLI installed,
choose a fresh output directory and run the same flow:

```powershell
New-Item -ItemType Directory -Force output/visual-demo | Out-Null
python -c "from pathlib import Path; from tools.capture_workloads import write_pcap; write_pcap(Path('output/visual-demo/compact-three-records.pcap'), count=3)"
otarchguard capture inspect output/visual-demo/compact-three-records.pcap
otarchguard capture map output/visual-demo/compact-three-records.pcap --model examples/capture-studio/architecture.yaml --output output/visual-demo/pending.json
```

Copy `pending.json` to `fictional-reviewed.json`. For each of these three unique
fixture candidates, set `decision` to `ACCEPT`, copy its candidate's `asset_id` and
`interface_id` to the corresponding `selected_asset_id` and
`selected_interface_id`, and record reviewer `fictional_fixture_author` with
rationale `Fictional deterministic fixture identity; not a real owner decision.`
Do not apply this fixture shortcut to actual network evidence.

```powershell
otarchguard capture compare output/visual-demo/compact-three-records.pcap --model examples/capture-studio/architecture.yaml --mapping output/visual-demo/fictional-reviewed.json --output output/visual-demo/pcap-report
```

Open `output/visual-demo/pcap-report/index.html` locally. Its first and only SVG
is the diagram source. Source SVG SHA-256:
`55186295c93c0c17f319e95c0090e8c1e563a4ad03459325f9583b0863587b8b`.
In the closure generation, the source overview HTML SHA-256 was
`95be7d260ea32236ee8b1a468f9e4dbc2fa6b68093715713e972fee88bb3059c`.

### Architecture Explorer source

The image is the complete bounded declared-architecture SVG from the actual
Architecture Explorer overview generated for the established fictional
`examples/remote-support/proposed.yaml` model:

```powershell
otarchguard explore examples/remote-support/proposed.yaml --output output/visual-demo/architecture-report
```

Open `output/visual-demo/architecture-report/index.html`. The model uses the
RFC 5737 ranges `192.0.2.0/24`, `198.51.100.0/24` and `203.0.113.0/24`.
One firewall asset has placements in three zones; repeated cards do not mean
three physical devices. Solid blue transport and solid purple native forwarding
lines are declared transitions, not evaluated permission or real connectivity.
This model-only view does not fabricate documentary provenance or owner history.

The released Explorer removes the native forwarding dash pattern so that native
relationships are solid, reserving dashed relationship lines for documentary
evidence. Its reused SVG text legend nevertheless retains "Purple dashed:
explicit forwarding". The image preserves both the real solid purple paths and
that original legend. In this Explorer view, read the purple routes as declared
forwarding; the mismatch is a known released presentation quirk, not a different
analytical result or a documentation claim that the product was corrected.

Source SVG SHA-256:
`64830b09f131407a3609d4c016282c8e2e76db911aac6b241913c727b0e96f55`.

a browser capture. No owner-supplied image is required for these PNGs. To add
actual application screenshots later, use a permitted ordinary local browser:

1. Generate the reports above and open their `index.html` files directly; no server
   is required. Start at 100% zoom with an approximately 1400-pixel viewport.

   the communication diagram with source/destination, port labels and model
   assessment text. An additional `findings.html` view can show descriptive links.

   architecture diagram. Keep the zone names, transition legend and interpretation
   visible; use a second region rather than cropping away a qualifier.
4. Exclude browser profile controls, local filesystem address bars and unrelated
   desktop content. Preserve application labels, uncertainty and fictional-data
   context. Record browser/version, viewport, zoom, exact report and package hash.
5. Inspect the proposed images for sensitive metadata before committing them;
   any newly tracked assets need exact public-inventory entries and source audits.

Local PNG decoding, dimensions, text visibility and Markdown references were
checked. Actual GitHub-hosted rendering must be checked in the authorized PR
preview after the owner chooses to push; it was not claimed before publication.
